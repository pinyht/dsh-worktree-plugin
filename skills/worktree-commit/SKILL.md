# worktree-commit

当用户说“开始提交”“提交”“commit”，或输入 `/worktree-commit` 时使用本 skill。

这是一个 model-invocable skill：只有用户明确要求提交时才使用；不要在 merge 后自动提交，也不要把普通讨论当成提交指令。

## 执行要求

- 必须在主项目目录执行。
- 先调用 `{{CLI}} commit-context [任务名]`。用户没给任务名时不要猜，交给 CLI 自动选择最近一次合并的任务。
- 读取输出里的：
  - 任务名和主项目状态；
  - `本次合并文件` 与 `注意: 主项目还有本次合并之外的改动`；
  - 任务会话记忆（用户要求 + 最后总结）；
  - 主项目 diff。
- 生成**中文提交说明**：
  - 第一行不超过 50 个字符，概括 why + what；
  - 正文 2-5 条，说明动机、主要改动、验证方式；
  - 不要写“由 AI 生成”“自动提交”等字样；
  - 不要编造没有做过的验证。
- 如果输出显示「主项目目录没有未提交改动」，告诉用户不需要 commit。
- 如果输出显示主项目有未解决冲突，停止，让用户先解决冲突。
- 如果 `注意: 主项目还有本次合并之外的改动` 非空，先停下来把额外文件列给用户，问是否一起提交；不要直接 `git add -A`。
- 用户已经明确说“开始提交/提交”时，直接执行：

  ```bash
  git add -A
  git commit -m "<第一行>" -m "<正文>"
  ```

  不要 push，不要修改代码，不要创建新分支。
- 提交成功后调用 `{{CLI}} mark-committed "<任务名>"` 更新任务状态；把 commit hash、提交说明和当前 `git status` 告诉用户。
- 如果任务目录落后主线，提醒用户需要时执行 `/worktree-sync <任务名>`。
